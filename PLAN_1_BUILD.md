## What "compiling" means here

`src/` does **not** build the game executables. `Magic.exe`, `Shandalar.exe`, `Shandalar.dll` and `CardArtLib.dll` are prebuilt binaries with no source in this tree. What `src/` builds:

| Target | Makefile | Role | Priority |
|---|---|---|---|
| **`ManalinkEh.dll`** | `src/Makefile` | All card code (~11,250 `card_*` functions) and the rules-engine extensions. Magic.exe calls into it through a jump table. | **Required.** This is the goal. |
| `Drawcardlib.dll` | `src/drawcardlib/Makefile` | Card rendering | Nice to have |
| `DeckDll.dll` | `src/deck/Makefile` | Deck editor | Nice to have |
| `ManalinkEx.dll` | `src/manalinkex/Makefile` | Small extension stub | Nice to have |
| `patches/*.exe` | `src/patches/Makefile` | Perl/C binary patchers for Magic.exe | Only if you change Magic.exe |
| `CardArtLib.dll` | `src/cardartlib/Makefile` | Art loader. Needs Boost 1.45 built for MinGW 4.6. | Skip it and keep the prebuilt DLL |

`Program/src/` is an **older snapshot** of the same tree: 94 card files instead of 132, and an older `defs.h`. Don't mix files between the two trees. Its one use is as a reference copy of `card_id.h` (see Step 2).

## Blockers found

1. **`src/card_id.h` is empty (0 bytes).** `defs.h` includes it, and the source uses 2,223 distinct `CARD_ID_*` names. The header is normally generated by `csv2dat.exe`, which `magic_updater/Magic_updater.bat` calls, but that tool is **not in the repo**.
2. **The source is newer than any card database in this tree.** I regenerated IDs from the newest CSV (`magic_updater/Manalink.csv`, 16,430 rows). 25 of the IDs the code uses still don't exist:
   - 15 from the Theros "Face the Hydra" challenge deck (`HYDRA_HEAD`, `NECK_TANGLE`, `THE_SLAYER`, …), all in `functions/challenge_mode.c` and `cards/theros.c`
   - 5 Unglued cards in `functions/counters.c`: `B_I_N_G_O`, `RED_HOT_HOTTIE`, `SHOE_TREE`, `TEMP_OF_THE_DAMNED`, `WATER_GUN_BALLOON_GAME`
   - `XENAGOS_ASCENDED` and `ECSTATIC_PIPER` (Journey into Nyx challenge deck), `DRENCH_THE_SOIL_IN_THEIR_BLOOD` (Archenemy scheme)
   - `AZORIUS_AETHERMAGE`. The CSV name generates `CARD_ID_AZORIUS_ETHERMAGE`. Every other Æ card in the code uses the `ETHER` spelling, so this one card was renamed upstream.
3. **`-Werror` everywhere, written for an old compiler.** The code targets MinGW GCC 4.6 (`boost_*-mgw46` in `cardartlib/Makefile`). A current `i686-w64-mingw32-gcc` (10–13) adds dozens of warnings, so expect the first build to fail on warnings rather than real errors.
4. **Machine-specific paths:**
   - `patches/Makefile` and `drawcardlib/Makefile` fail unless `which gcc` is `/d/mingw/bin/gcc` (the `testwhichgcc` target).
   - `build.pl` copies to `c:\magic2k\…`.
   - `deploy.bat` uses `c:\mingw\…`.
5. **No toolchain is running yet.** Docker Desktop is installed but not running. The WSL `Ubuntu` distro is installed and stopped. There's no native MinGW gcc on PATH. `src/make.exe` and `src/yasm.exe` are bundled.

Things I checked that are **not** problems:
- The ManalinkEh.asm jump table (11,386 `jmp near` entries) only references functions that exist in C. 67 of them are defined through macros like `ARCANE(card_blazing_shoal)`.
- `ct_all.csv` code addresses match the asm comments. For example, Dream Pillager is `0x200ee5e`.
- No tentative globals in headers, so GCC 10's switch to `-fno-common` should not cause duplicate-symbol link errors.

## Steps

### Step 1 — Set up the toolchain (WSL recommended)

```bash
wsl -d Ubuntu
sudo apt-get update && sudo apt-get install -y mingw-w64 make yasm perl python3
```

The existing `Dockerfile` installs the same packages and is equally valid once Docker Desktop is running. I recommend WSL because you can iterate faster without rebuilding an image.

Use the 32-bit cross compiler. Magic.exe is a 32-bit process, and the code assumes `-march=i586` and 4-byte pointers.

```bash
make -C src CC=i686-w64-mingw32-gcc CXX=i686-w64-mingw32-g++ \
     DLLTOOL=i686-w64-mingw32-dlltool OBJCOPY=i686-w64-mingw32-objcopy ASM=yasm
```

### Step 2 — Regenerate `card_id.h` (blocker 1)

Write `src/tools/gen_card_id.py`, a replacement for the header-generating part of `csv2dat.exe`. I prototyped and validated the naming rule against the old `Program/src/card_id.h`:

- Read `magic_updater/Manalink.csv` with `;` as the separator and Latin-1 encoding. Use columns `ID` and `Full Name`.
- Build the identifier: `Æ`/`æ` → `E`, strip accents (NFKD → ASCII), delete apostrophes, uppercase, collapse every other run of non-alphanumerics into `_`, trim `_`, then add the prefix `CARD_ID_`.
- Skip duplicate names (first ID wins). 15,718 rows → 15,641 entries, which matches the old header's count exactly.
- Write `typedef enum { CARD_ID_X = n, … } card_id_t;` inside a `CARD_ID_H` include guard, in the same format as `Program/src/card_id.h`.

Prototype: `C:\Users\cjohn\AppData\Local\Temp\claude\c--Users-cjohn-Downloads-Shandalar-master-working-Shandalar-master\537d7334-fa05-473b-a6a7-b20f9cf260d3\scratchpad\gen_card_id.py`

Add a Makefile rule so `card_id.h` rebuilds whenever `Manalink.csv` changes.

### Step 3 — Resolve the 25 missing IDs (blocker 2)

Card IDs are runtime data, not just compile-time constants. Each one indexes `Cards.dat`, `DBInfo.dat` and `Rarity.dat`, so **the CSV that generates `card_id.h` must be the same CSV that produced the `.dat` files the game loads.** In order of preference:

1. **Get the matching upstream data.** Look in the upstream GitHub repo's history for the commit where these card functions appeared, and take that commit's `magic_updater/Manalink.csv`, `ct_all.csv` and the `.dat` files. This is the only option that guarantees ID agreement.
2. **If upstream is unavailable, append rows.** Add the 24 cards to the end of `Manalink.csv` as IDs 16430+. Never insert rows in the middle: that renumbers every later card. Add matching `ct_all.csv` rows, then regenerate the `.dat` files. This requires `csv2dat.exe`; see Plan 2, Phase A.
3. **Fastest way to just compile:** add an `#if 0` guard or stub IDs for the challenge-deck and Unglued code. Add `#define CARD_ID_AZORIUS_AETHERMAGE CARD_ID_AZORIUS_ETHERMAGE` for the renamed card. This proves the toolchain but disables those features.

Recommended: do option 3 first to unblock Steps 4–6, and pursue option 1 in parallel.

### Step 4 — Get through compiler warnings (blocker 3)

1. In `Makefile-common`, temporarily remove `-Werror` and add `-fcommon` as a safety net. Run `make -k 2>&1 | tee build.log`.
2. Sort the warnings by type: `grep -o '\[-W[a-z0-9-]*\]' build.log | sort | uniq -c`. Usual suspects with modern GCC are `-Wcast-function-type`, `-Wimplicit-fallthrough`, `-Waddress-of-packed-member`, `-Wstringop-overflow/-truncation`, `-Warray-bounds`, `-Wmissing-field-initializers` and `-Wenum-int-mismatch`.
3. Silence the noisy families with targeted `-Wno-…` flags, then restore `-Werror`. Fix the warnings that point at real bugs (`array-bounds`, `stringop-overflow`) rather than silencing them.
4. Treat any real **errors** (not warnings) as the actual porting work. Expect a small number in inline asm, `__attribute__` usage or C/C++ prototype mismatches. `utility.cpp` uses `-std=gnu++0x`, which is still accepted.

### Step 5 — Link and verify the binary ABI

The DLL is only usable if its addresses match what `Magic.exe` and `ct_all.csv` expect:
- `manalink.lds` hard-codes about 350 Magic.exe addresses (for example `_player_counters = 0x4EF530`). It only works with the `Magic.exe` in this tree. Keep that exe.
- The linker script places `ManalinkEh.ao(.text)` first at image base `0x02000000` + `0x1000`. `_DllEntry` takes 6 bytes, so `_CodeSectionEx` must land at **`0x02001006`**. Each entry is 5 bytes, and the last one (`_card_seal_of_the_guildpact`) must be at **`0x0200ee63`**.

Add a `make verify` script that:
- runs `i686-w64-mingw32-objdump -d --start-address=0x2001006` on the DLL
- checks every `jmp` against the `; <hex>` comment in `ManalinkEh.asm`
- checks every `Code Address` in `ct_all.csv` that falls in the `0x0200xxxx` range points at the right `jmp`

If anything is off by one, every card in the game calls the wrong function.

### Step 6 — Runtime smoke test

1. Back up the shipped `ManalinkEh.dll` and replace it with the new build.
2. Launch `Magic.exe` (Manalink duel mode). Play a game with a deck that touches several eras: a basic land, an Alpha card, a Khans of Tarkir morph, a Shadows over Innistrad double-faced card, an Eldritch Moon card.
3. Launch `Shandalar.exe` and start a duel to confirm it loads the same DLL.
4. If it crashes, `dmp.pl` maps addresses to source lines. It expects `ManalinkEh.dbg`, which the Makefile already produces, plus gdb.
